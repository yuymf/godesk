# GoDesk 硬度验收规格（hardness acceptance）— 真实桌游基线

> 验收对象是 **GoDesk 插件管线**（自然语言 → 内核配置 → 呈现 → 迭代），不是某一商业桌游 IP 的官方规则复刻。
> 输入为**自写中文完整规则书**（忠实核心循环与胜负，**禁止**粘贴出版社 PDF / 原文）。缺口记引擎层单据，禁止给样例打补丁。

## 1. 目的

硬度证明：给定一份**完整自写规则书**（或等价多轮对话），管线能稳定产出**高质量可玩对局**或**诚实 unsupported**，且结果可冷启动复现。

| 证明 | 不证明 |
| --- | --- |
| NL 解析能选对/拒绝对应内核并写出可执行配置或诚实缺口 | 官方规则文本一字不差 |
| 规则书中的核心资源/行动/胜负进入 `rule-system` / content | 美术抛光、版权素材 |
| presentationFloor 给出可读盘面与 HUD | Collecta / 合 main |

## 3. 输入形态

优先 **A · 完整规则书冷启动**（`/chatgpt-plugin/new` 一次粘贴）。多轮 Studio 对话为可选补充。

规则书建议章节：概述、开局、回合循环、胜负、内容清单、呈现意图。长度约 60–180 行；必须可玩闭环描述齐全。

## 4. 成功标准（全部成立才算「通过」）

### 4.1 可玩闭环
生成 → Plan 确认 → 共享房间或「和电脑对战」/可玩预览 → **至少完整打完一回合核心机制**且不崩溃。

### 4.2 规则保真
claim vs observed：人数、核心资源、主行动、胜负条件；错绑 auto-battler 冒充通过 = **FAIL**。

### 4.3 呈现底线
盘面非空白；体裁 HUD 可读。无对应内核时须 **诚实 unsupported / draft**，不得静默 executable 假阳性。

### 4.4 冷启动
全新 `--persist-to` 重跑，层结论一致。

## 5. 记分

| 标记 | 含义 |
| --- | --- |
| **PASS** | SUCCESS 全过 |
| **部分** | 路由正确或诚实拒识，但核心可玩未落地（有缺口票） |
| **FAIL** | 错绑 / 假阳性 executable / 崩溃 |

缺口一律开 `docs/hardness/tickets/T00x-*.md`（层=解析/配置/内容/呈现/内核），通用修法，禁止题材特判。
