## decisions

- **走真实链路。** 第 0 轮用 Studio「确认玩法并开始试玩」自己开的那一局（UI 路径）。第 1–3 轮用 MCP `apply_project_patch` + `configure_render`，与 skill 示例同一入口。每轮之后走 Studio 迭代后的同一条路：`compile-build` job → `POST /api/builds/:id/sessions` → 打开新局的 `sessionUrl`。Room 读的是 build 快照，所以不重编译就看不到改动，这是现有设计，本刀不改。
- **三轮 patch。**
  1. `water: { enabled: true, shallow: "#3fa7c9" }`：桌面平面变成水面色（G3D-14 的简化表现，真水体等 G3D-08）。
  2. `lighting: { sun: { elevationDeg: 18 } }`：默认 52°，压低后受光变暗，盘面布纹法线更显。
  3. `materials.seat0 / seat1`：翻转棋的棋子颜色来自座位材质（RenderSpec 约定「座位色永远取 seat0–seat3」），`materials.piece` 改了不会体现在翻转棋上，所以第 3 轮改的是两色棋子，改成酒红 / 金，并调低粗糙度、加金属度。
- **断言 3D 舞台而不只是数据层。**
  - `TabletopScene3D`（懒 chunk，不计入核心与首页）给 `display: contents` 包装层挂了 3 个属性：`data-render-water`、`data-render-sun-elevation`、`data-render-seat0`，e2e 逐轮断言这 3 个生效值。
  - e2e 在页面里解码舞台截图，按轮检查：
    - 整图平均绝对差：水面 > 10，太阳 > 3，材质 > 0.1。棋子只占舞台约 1%，所以材质轮的整图差天然很小。
    - 水面轮：桌面采样区的蓝通道比红通道高 30 以上。
    - 太阳轮：桌面采样区变暗。
    - 材质轮：暖色高饱和像素增加 800 以上。
  - 本地实测：
    - 水面轮整图差 39.6；
    - 太阳轮整图差 14.6；
    - 材质轮整图差 0.25，暖色像素 0 → 2893。
- **截图不入库。** 设 `GODESK_E2E_EVIDENCE_DIR` 时，每轮另存桌面 1440×900 舞台截图，以及 iPhone 12 Pro 舞台截图和整页截图；CI 不设该变量，只跑断言。
- **不做。** 不改 worker room / bot，不改水体 shader；不改「Room 读 build 快照」的语义。
