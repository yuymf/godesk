## decisions

- **一个脚本，两道门。** `scripts/perf-emulate.mjs` 默认跑桌面模拟门（5 个画像），`--ci` 跑确定性子集。脚本自己启动 `wrangler dev --local`，并经 MCP 插件路径（generate → approve → compile → `create_shared_session`）建固定种子六角岛 Room，测的就是真实 Room 页。每个画像各建一个新 Room，保证初始局面一致。
- **自动对局** 是两个座位按种子（mulberry32）点击当前可用的合法动作按钮。被测页坐座位 0；不节流的 360×240 小驱动页坐座位 1，不参与测量。
- **`perf.ts` 只采集数据，不改画面。** `render3d:interactive` 标记总是打一次；逐帧采样、覆盖层与 `window.__godeskPerf` 只在 `?perf=1` 时存在。
- **泄漏检查。** `__godeskPerf.remount()` 原地拆掉并重建 3D 场景 10 次，断言三件事：
  - 每次挂载的 `renderer.info.memory` 与首次相同；
  - 卸载时应用几何体残留为 0；
  - 纹理残留只允许 three r186 的模块级 `emptyShadowTexture` 单例 1 个。
  - 由此查出并修复：SceneHost 卸载时没有释放平行光阴影贴图（新增 `sun.shadow.dispose()`）。
- **draw call 预算。** main 上固定种子初始局面为 158 次 draw call，超过 high 档 ≤ 150。number token 只有 0.06 高，阴影不可见，取消它的阴影投射后降到 140。注意：桌面模拟门在 120 秒对局后达到约 170（定居点 / 道路增多），这是留给 G3D-04 / 07 的预算风险（实例化、合批），记入 STATUS。
- **harness 查出的 SceneHost 缺陷（已修）。** `renderer.setSize(..., false)` 没有设置 canvas 的 CSS 尺寸，DPR > 1 时 canvas 按后备缓冲宽度排版：Pixel 7 画像中为 824 px，把 412 px 的页面撑宽一倍。已在 SceneHost 中固定 canvas 为 `display:block; width/height:100%`。
  - 余下的横向溢出（451 px）来自 2D `HexIslandBoard` 的 `.hex-island-stage`，由 G3D-18 删除，记入 STATUS。
  - 同一次排查还发现：CDP 触摸模拟下 Playwright 的 click 可操作性检查会超时，自动对局改为失败时退回 `dispatchEvent("click")`。
- **档位。** G3D-06 前没有自动分级，档位读 `?tier=`，默认 high。移动画像按目标档位 low 评估 draw call、三角形与 GPU 预算，会如实失败；JSON 同时写 `tier.expected` / `tier.actual`。
- **Lighthouse CI。** 使用 temporary public storage（免费、无需密钥）加 workflow artifact，不需要新 secret 或付费服务，所以不存在阻塞。
- **Lighthouse 基线。** 本机（`main` @ `8fbbc6c`）：首页 Performance 0.87、LCP 3 173 ms、TBT 0、CLS 0；Room 0.57、TBT 4 697 ms、CLS 0。CI（本 PR revert 临时提交后的运行 37376770113）：首页 0.81 / 0.86 / 0.84、LCP 3 499 ms；Room 0.56 / 0.52 / 0.52、TBT 153 868 ms（SwiftShader 持续渲染，不是有效信号）、CLS 0.132。Performance 按 §4.6.3「不低于基线」取 CI 3 次运行的最低值（首页 0.81、Room 0.52，error）；首页 LCP、Room TBT、Room CLS 阈值不改，级别为 warn，提 §9 问题；首页 TBT ≤ 200 与首页 CLS 保持 error。详见 `docs/perf/emulation-protocol.md` §6.1。
- **CI 托管 runner 故障。** githubstatus 自 2026-10-06 03:12（Asia/Shanghai）起报 Actions major outage，#110 的前几轮 job 均报 “not acquired by Runner”（runner=null，与代码无关）。05:30 前后 runner 恢复，临时超预算提交 `c560b67`（及其上的 STATUS 提交 `9b035f2`）的 CI 按预期失败：run 37374834984 在 `perf:ci` 失败（drawCalls 340 > 150、残留几何体 1），run 37374835034 在 Lighthouse 失败（首页 TBT 1 205 > 200、Performance 0.63）。revert 后（`aed5e03`）Verify 通过（run 37376769889）。
- **benchmarkIndex** 直接调用 Lighthouse 的 `computeBenchmarkIndex`（经 `@lhci/cli@0.15.1` 依赖解析），不复制代码。
