## decisions

- **生成即写 render。** `materializeRuleSystem` 对 table / scene / hybrid 写入 `defaultRenderSpec(null, kind)`。此时还没绑定 Kernel，所以写的是通用桌面默认（与 G3D-14 的底座一致）。生成计划批准、configure_* 绑定空间 Kernel 后，已有的 `ensureRuleSystemRender` 会把「未改动的默认」换成该 Kernel 的 preset 与 bindings；创作者改过的 render 保留。configure_* 本身因此不需要逐个改代码，worker 测试断言了翻转棋批准后 render = `defaultRenderSpec("disc-flipping-v1", "table")`。
- **`configure_render` 是局部 patch，不是整块替换。** `renderPatchSchema`（`src/creator/render-spec.ts`）。合并规则：
  - 各段只合并一层：camera、lighting.sun / hemisphere / shadow、water、motion，以及 audio 的音量；
  - materials 按键合并，新键必须是完整材质；
  - bindings 与 audio.cues 整块替换。
  - 合并结果必须再过 `renderSpecSchema` 与 `renderSpecIssues`：材质存在、资产已登记许可证、俯仰角区间有效。
  - 空 patch 和未知键（strict）都拒绝。
- **只允许空间盘面。** 非空间盘面返回 400「当前盘面不是桌面 / 场景类」；非法 patch 返回 400，render 不变。`configure_render` 计入 `changesGenerationCandidate`，有待批生成计划时会刷新计划。
- **MCP。** 工具 `apply_project_patch` 的 discriminated union 加 `configure_render`，描述里给出 3 个 patch 示例。不新增工具，沿用乐观版本与幂等键。
- 明确不做：3D Room e2e 与逐轮截图（等 G3D-14）；`configure_disc_flipping` / `configure_hex_settlement` / `configure_network_route` 进 MCP（现状是只在生成链路使用，不在本刀范围）。
