## decisions

- **不等素材，先落引擎。** `src/render3d/audio/sources.ts` 用 Vite `import.meta.glob("../../../assets/audio/*.mp3")` 与 `sfx-*.json` 发现素材。#111 / #112 合入前 glob 为空，引擎退化为「只记 cue 日志、不出声」，构建与测试都不依赖未合入的文件；合入后无需改代码即可出声。片段名按 #111 的 `sfx/*`，曲目顺序按 #112 的清单顺序（tide-harbor = 主题，crystal-shore = 平稳，observing-star = 终局，属推断，待 Track B 确认）。
- **cue 从房间快照差量推导。** 客户端拿不到 kernel 的 `PlayEvent` 流，只有 `acceptedActions`（`actionId` = `action.type`，带动作后的 `SessionState`）。`cuesForRoomDelta` 按动作顺序映射 cue；`roll_dice` 后按本座位资源增量出 `gain`（每种资源 1 次，变体按 [wood, brick, sheep, wheat, ore]）；`move_robber` / `play_knight` 抢到资源时追加 `steal`；`bank_trade` / `player_trade` 取 trade 变体 bank / accept；status 首次变 complete 时出 `win` / `lose`（观战者听 win）。首次进房不回放历史。
- **UI cue。** 房间内可用按钮的 hover → `hover`（触摸指针不出，80 ms 节流），点击 → `select`；RoomView 报错 → `illegal`；声音设置面板开合 → `panel`，开关 / 曲目 → `toggle`。拾取（G3D-04）合入后，3D 热点也走同一个按钮委托。
- **howler 用 core 构建**（`howler/dist/howler.core.min.js`，不含 spatial），与 RoomAudio 一起作为懒加载 chunk，命名落入 `render3d-*`，计入 render3d 核心 210 KB 预算（实测 render3d 核心合计 189.24 KB；音频 chunk 11.79 KB gzip，A8 的 tween + howler ≤ 15 KB 仍有余量）。
- **声音设置做成右下角浮动按钮**，不插进盘面区块，避免与 #109 改动的盘面 JSX 冲突，也不受手机视口下 2D 盘面溢出影响。
- **AudioContext 状态写到 DOM**（`[data-sound-settings][data-audio-context]`）。排查发现 Playwright 的 `evaluate`、`waitForFunction` 以及定位器查询都以用户手势执行，会让页面提前获得用户激活，所以之前测到的 AudioContext 永远是 running；静态页对照实验证明，Chromium 的真实策略是首次 tap 前 suspended、tap 后 running。e2e 因此在 AudioContext 建好之前只做被动等待（导航、等音频 chunk 的网络响应、定时），之后读 DOM 属性。
- 明确不做：素材本身（G3D-26 / 27）、音量响度处理、低档只加载海浪的自动判定（等 G3D-06 档位；引擎已支持 `lowTier`）、带声录屏（素材合入后补）。
